## 3. 핵심 기술 심층 마스터 (Deep Tech Knowledge)

### ① Salt(솔트) 보안 해싱의 원리와 필요성
- **단순 해싱의 한계**: 비밀번호 "1234"의 SHA-256 해시값은 전 세계 어디서나 항상 똑같은 고정값(`03ac67...`)이 나오므로, 해커가 미리 만들어 둔 사전 표인 **레인보우 테이블(Rainbow Table)**로 1초 만에 비밀번호를 알아낼 수 있습니다.
- **Salt 결합 메커니즘**: 회원가입 시 `secrets.token_hex(16)`으로 생성된 32바이트 난수를 비밀번호 뒤에 붙여 `hashlib.sha256((password + salt).encode())`로 해싱합니다. 두 사용자가 같은 비밀번호를 써도 **DB에 저장되는 해시값이 완전히 다른 랜덤 해시값**이 되므로 레인보우 테이블 공격이 100% 무력화됩니다.

### ② 4대 Flash 모델 캐스케이딩 폴백
- `gemini-3.5-flash-lite` ➔ `gemini-3.6-flash` ➔ `gemini-3.7-flash` ➔ `gemini-3.5-flash` 순서로 등록하여, 503 과부하나 429 속도제한 발생 시 0.5초 이내에 다음 순위 모델 세션으로 자동 전환되어 100% 무중단 복구됩니다.

## 4. 평가위원/청중 예상 Q&A 5선 및 모범 답변

#### Q1. Salt(솔트)를 넣으면 비밀번호 보안이 왜 안전해지나요?
> **답변**: "동일한 비밀번호라도 사용자마다 다른 고유 난수(Salt)를 결합하여 해싱하므로, DB에 저장되는 해시값이 사용자마다 완전히 달라집니다. 따라서 DB가 유출되더라도 해커가 미리 계산해 둔 레인보우 테이블 공격으로 원래 비밀번호를 역추적하는 것이 불가능합니다."

#### Q2. 503 과부하나 404 모델 폐기 에러는 어떻게 방어했나요?
> **답변**: "지원이 종료된 구버전 모델을 완전히 제거하고 현재 가장 쿼터가 넉넉하고 빠른 `gemini-3.5-flash-lite`를 1순위로 배치했습니다. 또한 4대 Flash 모델 간 캐스케이딩 폴백 루프를 구축하여 특정 모델 장애 시 0.5초 내에 예비 모델로 자동 전환되도록 복원력을 구현했습니다."

#### Q3. LangGraph 시각화(`draw_mermaid`)를 도입한 이유는 무엇인가요?
> **답변**: "에이전트의 조건부 의도 분기(식단/운동/RAG/일반)와 Self-RAG 품질 검증 흐름을 Mermaid 다이어그램으로 가시화하여, 시스템의 구조적 제어 흐름과 안정성을 직관적으로 입증하기 위함입니다."

#### Q4. 식약처 DB 검색 시 환각이 0%인 이유는 무엇인가요?
> **답변**: "LLM에게 직접 칼로리를 생성하게 하지 않고, `search_food_nutrition` 파이썬 도구를 바인딩하여 식약처 CSV 파일에서 정확한 행을 탐색한 실측 JSON 데이터만 반환하도록 강제하기 때문입니다."

#### Q5. 순 칼로리(Net Calories) 지표의 임상적 의미는 무엇인가요?
> **답변**: "`순 칼로리 = 섭취량 - 운동 소모량`을 실시간 계산하여, 운동을 통해 획득한 칼로리 버퍼를 대시보드에 즉각 반영함으로써 지속 가능한 다이어트 동기부여를 제공합니다."
